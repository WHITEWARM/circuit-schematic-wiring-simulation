# 阶段复核与证据记录

用于电路实现、模块合并、故障修复和优化。每个模块及工作阶段完成后，Codex 暂停修改，读取该版本的原生文件、输出或图像，按独立预期复核，再决定下一步。复核本身由 Codex 执行；不要求用户逐项批准，也不暗示另一个独立代理已经参与。

## 流程与检查点

| 阶段 | Codex 必须核对 | 推进依据 |
|---|---|---|
| 要求与确定元件 | 指定型号/实现限制、实物封装、采购依据、供电、引脚映射、模型覆盖范围、可用执行接口 | 元件及模型记录；最小原生工程可修改、连接、运行、保存重开 |
| 架构与布局 | 各模块输入输出、参考地、驱动负载、时序、误差预算、完整走线空间 | 接口约定和可检验的预期；不存在未解决的接口冲突 |
| 每个模块的实现 | 元件、外围参数、原生线端点、复位/使能、独立测试输入及单位 | 模块原生图和实际参数与设计一致 |
| 每个模块的局部验证 | 已知输入、上下限/代表值、边界、启动和多次更新；显示与计数等按下文专项检查 | 实测满足该模块通过条件；保存波形/数据/原生图像及耗时 |
| 每组模块间连接 | 去除临时测试驱动；供电/地连续；接口电平、极性、边沿、负载和启动顺序 | 由真实上游驱动的链路通过；设计、可见、求解连接一致 |
| 整机功能复核 | 默认运行、非零输入、用户入口改值、进位/边界、连续更新、关键断线及恢复 | 原生工程证据覆盖要求；显示数值和上游量值相符 |
| 效率复核 | 首次有效输出、后续刷新、仿真时间、真实耗时、界面等待；同条件优化前后结果 | 达到约定目标，或明确报告基线及尚存瓶颈；正确性无回退 |
| 自动几何检查与看图 | 重复/重合线、越界、遮挡、线距、交叉歧义、文字尺寸；整图和拥挤局部 | 几何报告问题已修复或有针对性的复核证据；原生渲染图可追踪 |
| 保存重开与交付 | 最终路径、版本、输入单位、模型依赖、默认参数、再次修改输入与输出 | 检查记录对应最终文件；缺失证据明确标为未验证 |

每次修复回到问题所属阶段，只重验受影响模块、连接及下游功能。局部通过不能免除真实接口合并测试；排版修改后连接比较必须重新生成，不能复用旧坐标和旧网表。

## 显示和用户输入专项

- 显示模块使用独立已知码型，检查适用的 `0`、`1`、`8`、小数点和逐位点亮；结合实物手册核对共端极性、段脚、限流、消隐和灯测。
- 同时记录段端电压/电流和目标软件里的实际显示。只有波形或网表证据时，原生显示项仍为未验证。
- 计数/转换模块使用已知脉冲或输入，核对采样、计数、锁存、清零先后顺序；运行到足以观察至少两次后续更新，不能只观察首帧。
- 整机从用户实际会操作的属性入口改值，检查修改确实进入传感器/转换链路。测试“默认值 → 不同非零值 → 返回值”，并观察足够更新周期。输入范围适用时可用 `25 → 37 → 25`，但这些是示例测试点，不是模型固定答案。
- 测试电压与物理量分别标单位。例如输入若为传感器输出电压，按灵敏度换算；若数值表示温度，则明确这是仿真控制量，不能混用。

## 连接和可读性专项

先按 [可见接线参考](visible-wiring.md) 取得独立的引脚分组及原生对象几何，再运行连接比较和几何审查。每条问题记录应能定位到元件、线段、坐标或截图区域。

Codex 查看最终原生整图，确认模块顺序、全部跨模块线路、电源/地回路、边缘留白；再查看显示/控制等拥挤区域和自动报告指出的区域，确认端点、分支点及非连接交叉含义。按用户预期屏幕/纸张尺寸检查，不以无限放大后的可读性代替实际可用性。额外解释放在图外。

自动几何检查只覆盖导出对象；无法提取原生几何时，保留“自动检查未验证”，可继续看图检查但不能将其冒充已运行脚本。反之，脚本无问题也不代表图像已复核。

## 仿真效率专项

从模块阶段开始记录代表性测试耗时。先解释电路本身需要的启动/积分/门控时间，再检查单位仿真时间所需计算量及界面开销。

比较优化前后时记录同一测试输入、仿真跨度、初态、观察量和设置差异，同时比较输出。需要覆盖至少多个有效更新周期，不能截短运行以掩盖停更。加快时钟、缩短积分窗口、修改步长或替换模型时，重查受影响的误差、漏计、边界和端口依赖，按 [验证与优化](verification-optimization.md) 操作。

## 精简记录格式

可在项目已有记录中使用下面的列，不要求为每个检查点新建文件：

| 模块/阶段 | 原生文件版本或散列 | 输入/设置与单位 | 独立预期与容差 | 实测与证据路径 | 仿真跨度/真实耗时 | 结论与修复 |
|---|---|---|---|---|---|---|

结论为通过、失败、未验证或不适用；不适用必须有原因。截图、实际求解数据、几何导出和检查报告均注明来源版本。证据不足不写通过；更新文件后使相关旧记录失效。用户最终验收可以补充证据，不能替代 Codex 已能完成的复核。
