# 阶段复核与证据记录

用于电路实现、模块合并、故障修复和优化。每个模块及工作阶段完成后，Codex 暂停修改，读取该版本的实际原生电路、连接和运行结果，重新对照项目要求及电气原理，发现并修复错误。复核不是确认“文件存在”或“流程已走完”。

默认由当前 Codex 执行复核，不要求用户逐项批准，也不暗示另一个独立代理已经参与。

## 从具体项目推导检查项

1. 取得本项目的功能和指标、允许器件及实现方式、所选器件手册、模块接口约定，以及当前待复核的实际文件版本。
2. 按该模块或工作部分的作用确定可能的电气问题。候选维度包括供电和参考地、引脚映射、连接拓扑、信号方向、电平、负载/驱动、工作范围、偏置、反馈、时序及所需动态行为。只选与当前实现有关的项，并补上项目特有约束；不能把候选维度当作封闭的固定清单。
3. 为适用项指定检查对象、方法、输入条件、观察量和通过标准。标准来自项目要求、数据手册、计算或独立规格；缺少关键依据时保留未验证，不能随意选择一个易通过的阈值。
4. 直接读取实际电路及求解连接、检查参数、重算关键关系，并运行需要的局部或整机实验。检查结果应能指出问题所在元件、引脚、网络或电气过程。
5. 发现问题后定位原因，修复对应部分，再重验受影响模块及下游行为。检查到的异常不能通过改预期、改显示答案或补装饰线来掩盖。

例如，放大模块可能需要复核偏置、输入共模范围、闭环反馈及输出负载；数字模块可能需要复核逻辑电平、控制极性和时序。这些只演示推导方法，不要求每个项目都存在这些模块或照搬这些检查项。

## 各阶段如何复核

| 阶段 | 复核对象与方法 | 推进依据 |
|---|---|---|
| 要求与确定元件 | 核对所选器件和实现路径能否满足本项目条件，检查手册、模型映射、采购封装和实际执行能力 | 条件兼容，模型范围及未覆盖项清楚；所需最小原生操作已验证 |
| 架构与布局 | 复算关键参数，检查模块接口及实际可见走线空间 | 接口约定能匹配，关键指标有依据，布局可容纳真实线路 |
| 每个模块的实现 | 对照设计读取实际元件、参数、引脚及求解连接，查找当前模块的电气错误 | 实际实现与设计一致，相关器件工作条件满足 |
| 每个模块的局部验证 | 用本模块推导出的刺激、负载和观察量检查功能及电气行为 | 实测满足该模块适用的项目标准，证据可复现 |
| 每组模块间连接 | 核对实际跨模块连线、接口电气兼容性及真实负载下的行为 | 设计、可见、求解连接一致；相连模块能按接口要求协作 |
| 整机功能复核 | 以完整电路运行结果逐项复核项目要求，查局部验证未暴露的交互问题 | 相关工况和指标有实际证据，不能用模块通过替代整机通过 |
| 效率复核 | 分析本项目的电路等待、求解耗时和界面开销，按相同测试条件比较优化结果 | 瓶颈与变化有依据，项目所需电气行为及正确性没有回退 |
| 自动几何检查与看图 | 检查实际原生布局，结合几何报告、整图及拥挤区域判断线路是否清楚可追踪 | 问题已修复或逐项有复核证据；排版未改变正确连接 |
| 保存重开与交付 | 在最终路径检查参数、依赖和项目所需的实际运行行为 | 检查证据对应最终版本，未验证项按事实交付 |

每次修复只重验受影响范围。引脚、模型、连线、参数或仿真设置变化会使相关旧记录失效；布局调整后重新生成几何和连接，不能复用调整前的数据。

## 连接和可读性的独立证据

按 [可见接线参考](visible-wiring.md) 分别取得设计、可见导线及实际求解的外部引脚分组，进行比较。检查实际模型是否绕过端口；针对本项目关键传输路径选择有意义的断线/恢复试验，按电路性质确定预期响应。

整机连接和功能复核后，对最终原生对象执行自动几何检查。Codex 随后查看原生整图与相关局部，核对自动报告指出的问题，以及端点、分支、非连接交叉、留白和目标尺寸可读性。额外解释放在图外。

无法取得原生几何时，自动检查项为未验证；可继续看图，但不能说脚本已经完成检查。只有几何报告而无实际图像，也不能声称渲染清晰度已复核。合法交叉等提示可以逐项以原生连接及图像证据说明，不能统一忽略。

## 功能与效率按项目选择方法

按模块类型选择工作点、扫参、交流、瞬态、数字事件或其他适合的验证方法；测试点、边界、持续时间及误差标准均由本项目功能推导。只需静态行为的模块不强加刷新周期；要求动态行为的电路不能用一个静态值验收。若任务包含原生仪表或动画，其界面行为与求解数据分别验证。

从模块阶段保留足以定位瓶颈的耗时证据；优化前后比较同一项目工况的正确性和耗时。替换模型、调整步长或改变结构后，按实际受影响的物理过程和功能选取复测范围。详细方法见 [验证与优化](verification-optimization.md)。其中故障案例仅在现象和电路类型适用时查阅，不是所有电路的必做清单。

## 精简记录格式

可使用项目已有记录，保留以下信息即可，不要求每个检查点单独创建文件：

| 模块/阶段与版本 | 项目要求/电气依据 | 实际检查对象 | 条件、方法及预期 | 实测与证据 | 结论、问题及修复 |
|---|---|---|---|---|---|

结论为通过、失败、未验证或不适用；不适用有原因。运行测试时按需要补充设置、仿真跨度和真实耗时。证据不足不写通过；依赖项失败或未验证时可以继续无关工作，但不能将依赖它的整机功能标为通过。用户最终验收可补充证据，不能代替 Codex 已能完成的复核。
