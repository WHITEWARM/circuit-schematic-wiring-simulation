# Multisim 实现注意事项

仅在 Multisim 任务中读取。本参考来自一次 Multisim 14.3 温度计工程的实际实现经验；内部字段、接口和模型兼容性需要在当前版本用最小文件复核，不视为公开稳定 API。

## 选择可运行的实现路径

尊重用户指定版本及禁止的操作。正常使用可用的原生功能、已安装接口或已验证文件生成工具；用户要求避免打开元件库时，不再反复访问该库。

曾有工程使用本机原生求解接口和离线文件处理完成验证，这些能力不随本 skill 提供。先发现当前机器实际可用的工具、模块和接口，核对依赖与位数，不能假定存在某个私人 `MultisimClient`、旧工作目录或编解码工具。

使用程序化原生文件修改时，先从最小可打开样例开始，完成“读取—修改一个参数或一根导线—保存—原生重新打开—求解”的验证，再扩大规模。`.cir` 导入结果与原生 `.ms14` 需要分别检查；不把 ngspice 自检当作 Multisim 已通过。

如果内部文件结构或接口尚未验证，先验证它们或换用允许且可用的路径。不能伪造 `.ms14`，也不能承诺任意版本都支持相同的离线生成方式。

## Multisim MCP 配套接口

加载本 skill 不依赖 MCP；自动完成 Multisim 文件操作、仿真和导出需要 MCP、原生 API 或其他经过验证的执行接口。MCP 是工具接入方式，具体的显示、模型和布线能力取决于服务端及本机环境，不能因成功连接就全部判定可用。

可参考本次使用的非官方 [multisim-mcp 项目](https://github.com/yxy050208/multisim-mcp)，按其当前说明安装并固定所选版本。Windows 上的 Multisim 自动化需要本机已授权的 Multisim 及兼容的 32 位 COM worker；MCP 前端与 worker 可以使用不同位数。原生工程生成还可能需要该项目规定的编解码器和本机模板包。各项按上游所选版本的安装/兼容说明核对，不复制他人个人目录作为可移植安装方案。

建议配置步骤：

1. 按上游说明安装运行时及所需本地模板。模板从使用者自己的已授权安装生成；准备期间保存现有工作，遵守本任务禁止访问元件库等操作限制。
2. 先运行上游只读 `doctor` 或 MCP `runtime_status`，确认依赖、位数、模板和工具状态；只读诊断就绪不等同于电路已验证。
3. 使用上游 `config --client codex` 生成适合该机器的配置片段，核对 Python、worker、模板路径。Codex 配置入口见 [官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。不要覆盖使用者已有的其他服务配置。
4. 重新加载连接后，发现当前可调用工具的实际参数；在任务授权范围内完成最小工程的打开、改参数、原生连线、运行、保存重开及关键断线试验。
5. 有数码管或仪表的任务，另外验证原生动画。若高层实验实际运行的是独立命令引擎网表，记录该证据来源，再单独验证最终 `.ms14` 原生运行行为。

本仓库没有捆绑 MCP 服务端、NI 程序、厂商模型、编解码器或从安装中提取的模板，也未提供原生几何导出适配器。安装指导不能替代新机器上的最小路径验证。几何审查所需数据按 [可见接线参考](visible-wiring.md) 从实际工程取得。

## 元件、端口和导线的一致性

下列是曾观察到的内部记录，用于定位而非直接照抄模板：

| 记录或字段 | 应核对的关系 |
|---|---|
| `CiComponent`、`CiPort` | 元件实例、模型端口、外部引脚及端口所连节点 |
| `CIITPinSymbolComp`、`CIITPinConnectorComp` | 图上引脚与实际连接器的对应及引用是否有效 |
| `CIITLinkComp` | 原生导线的端点引用、节点、折线坐标及可见样式 |
| `CiaSpiceTmpltExprt` | 模型模板端口/参数展开是否与当前元件一致 |
| `CIITDiagram` 中的仿真状态 | 保存和重开后实际采用的分析设置 |

只改图上文字不能证明器件参数已修改；只改模型节点不能证明导线已经画出。检查元件属性、模型参数、引脚与连接器引用、原生导线和实际导出网表是否相符。

利用模板或载体创建器件时，同时修正符号、属性窗口、端口顺序和实际模型，避免图上显示“温度传感器”而属性仍是无关的电阻参数。用户需要调整的量必须有明确、有效且带单位的入口。

复制模块必须处理实例标识与连接器引用，不只是更改位号。内部模型采用局部作用域，通过外部端口正常连接。

## 本次经验中应保留和应改进的部分

保留：关键元件最小测试、分模块测试、实际原生文件运行、模型范围说明、保存重开检查、参数调整验证、完整线路绘制、精度与速度分别测量。

改进：曾有快速功能版把数字事件连接固定编译到模型中，用户改数字导线后必须再生成模型。该方式不满足当前 skill 的可见接线要求，即使原图和原输出一致，也不能作为常规实现方式复用。数字事件原语必须通过当前电路的可见端口和原生连接工作，并通过改线试验。

曾有论文图使用同名标签表达模块间连接，电气含义可解释，但不满足完整可见接线需求。新图必须画出跨模块线路，并把电源和地也纳入连续连接检查。不能仅在导出 PDF 上补线而原生文件仍靠隐式连接。

## 显示与输入测试

原生数码管需要单独测试已知段码、极性、限流、共端、消隐端和显示阈值；普通 LED 等效电路的电流通过不代表原生动画通过。共阴/共阳和实物脚号以所买器件手册为准。

可调温度等外部条件与电路电压不同。若用电压源数值代表温度，明确其为仿真控制量和输入单位，同时核对真正传感器输出；不能让用户猜应输入 `25` 还是 `0.25`。实物对照图按要求处理这类测试源。

计数显示需要检查门控、计数、锁存、清零的先后关系，并覆盖至少足以观察连续更新的区间。单个有效数字不足以排除持续复位、只更新一次或边界漏计。

## 文件交付

以用户最终使用的文件名和路径为准。用户改名后更新说明，不恢复旧文件名覆盖用户文件，也不交付已经过期的说明。

保存后重新打开并运行最终文件，核对实际参数、模型和仿真设置。模型嵌入与单文件可移植性需要单独检查；未经验证不能说只发 `.ms14` 一定可用。

论文输出、模块图、诊断网表和整机原生文件分别按其实际用途命名。最终显示未由界面观察时，明确已经验证的求解数据范围，留给用户的界面验收项不得写成已通过。
